# Contributing

Thanks for your interest in contributing to this project. We appreciate time, effort, and feedback from the community.

## Ways to Contribute

- Report bugs and suggest improvements
- Improve documentation
- Submit feature requests
- Help with code reviews and testing
- Share ideas for better UX and architecture

## Development Workflow

1. Fork the repository and create your branch from the main branch.
2. Install dependencies:
    - `composer install`
    - `npm install`
3. Copy the environment file and configure your local values:
    - `cp .env.example .env`
4. Run the setup for the project:
    - `composer run setup`
5. Make your changes and verify them with the relevant tests or checks.
6. Commit your work with clear, descriptive messages.
7. Open a pull request with a clear explanation of the problem and solution.

## Coding Standards

- Follow the existing project conventions and architecture.
- Keep changes focused and easy to review.
- Write descriptive commit messages.
- Add or update tests when changing behavior.
- Prefer small, well-scoped pull requests.

## Pull Request Guidelines

Before opening a PR, please ensure that:

- Your branch is up to date with the base branch.
- The code passes the relevant checks and tests.
- The change is documented when needed.
- You describe the purpose and scope of the change clearly.

## Reporting Issues

When opening an issue, please include:

- A clear title
- A detailed description of the problem
- Steps to reproduce
- Expected vs. actual behavior
- Relevant environment details

## Code of Conduct

This project follows a Contributor Covenant Code of Conduct. Please read the [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md) before participating.

## Questions

If you are unsure about something, open a discussion or issue first so we can clarify the approach before you spend time on a large change.
