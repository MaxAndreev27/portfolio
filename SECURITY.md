# Security Policy

## Supported Versions

The project is under active development. We aim to address security issues in the latest version on the main branch.

| Version                          | Supported           |
| -------------------------------- | ------------------- |
| main / latest development branch | ✅ Supported        |
| older released versions          | ⚠️ Best effort only |

## Reporting a Vulnerability

Please do not disclose security issues publicly until they have been investigated and a fix is available.

To report a vulnerability, use one of the following options:

- Open a private security advisory through GitHub
- Contact the maintainer directly via the repository owner contact details

Please include:

- A description of the vulnerability
- Steps to reproduce it
- Impact assessment
- A suggested fix, if available

We will acknowledge receipt as quickly as possible and work to validate and address the issue responsibly.

## Response Expectations

- Initial acknowledgment within a few business days
- Investigation and triage of the report
- Coordination of a fix and release if applicable
- Public disclosure only after the fix is released or a clear mitigation is in place

## Security Best Practices

When contributing or deploying this project, please ensure that you:

- Keep dependencies updated
- Use secure environment variables for secrets
- Avoid exposing credentials in logs, code, or issue reports
- Use proper production configuration and deployment controls
